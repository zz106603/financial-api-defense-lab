# Threat Model

## 1. 목적과 범위

금융 API에서 보호할 자산과 공격자, 신뢰 경계, 주요 위협을 정의한다.

MVP는 유효한 인증 자격을 가진 고객 또는 제휴사가 권한 없는 금융정보에 접근하는 상황에 집중한다. 특정 금융기관의 실제 침해사고를 그대로 재현하지 않는다.

## 2. 보호 자산

| 자산 | 보호 목표 |
|---|---|
| 계좌정보 | 소유권·위임 권한 없는 조회 방지 |
| 거래내역 | 허용 범위 외 조회 및 노출 방지 |
| AccessGrant | 무단 권한 생성·회수·재사용 방지 |
| 인증정보 | 요청 주체 위조 및 토큰 정보 노출 방지 |
| AuditEvent | 접근·권한 변경 추적 및 민감정보 보호 |
| SecurityAlert | 이상 접근 탐지 결과 보존 |

모든 금융정보는 합성 데이터를 사용한다.

## 3. 공격자 모델

| ID | 공격자 | 가능한 시도 |
|---|---|---|
| A01 | 인증된 일반 고객 | 다른 고객 계좌 조회, 타인 권한 변경 |
| A02 | 인증된 제휴사 | 위임받지 않은 계좌·거래내역 조회 |
| A03 | 권한이 회수된 제휴사 | 기존 인증 수단을 이용한 재조회 |

인증 자체를 우회하거나 서버를 장악하는 공격은 MVP의 핵심 검증 대상이 아니다.

## 4. 신뢰 경계

| ID | 경계 | 보안 원칙 |
|---|---|---|
| TB-01 | 외부 요청 → 인증 | 클라이언트가 주장한 고객·제휴사 ID를 신뢰하지 않음 |
| TB-02 | 인증 → 업무 인가 | 인증 성공만으로 금융정보 접근을 허용하지 않음 |
| TB-03 | 인가 → 데이터 접근 | 실제 객체 소유권·위임 범위를 데이터 조회 시 검증 |
| TB-04 | 데이터 → API 응답 | 허용된 정보만 반환하고 불필요한 필드 제외 |
| TB-05 | 서비스 → 감사 기록 | 접근 결과를 기록하되 토큰·금융정보 원문 제외 |

## 5. 주요 위협

| ID | 위협 | 위험도 | 대응 방향 |
|---|---|---|---|
| T01 | 다른 고객의 계좌 ID로 무단 조회 | Critical | 객체 소유권 검증 |
| T02 | 다른 제휴사에 위임된 정보 조회 | Critical | 실제 요청 제휴사의 권한 검증 |
| T03 | 허용된 조회 범위 초과 | High | 권한 종류별 검증 |
| T04 | 회수된 권한 재사용 | Critical | 현재 권한 상태 확인 |
| T05 | 허용되지 않은 응답 필드 노출 | High | 응답 필드 제한 |
| T06 | 여러 계좌에 대한 반복 무단 접근 | Medium | 감사 기반 이상 접근 탐지 |
| T07 | 접근 거부·권한 변경 기록 누락 | High | 감사 이벤트 검증 |
| T08 | 감사 기록의 민감정보 노출 | High | 로그 데이터 최소화 |

위험도는 프로젝트의 초기 정성적 평가이며 실제 금융기관에 대한 위험 평가 결과가 아니다.

## 6. 보안 원칙

- **Deny by Default:** 확인되지 않은 권한은 거부한다.
- **Least Privilege:** 필요한 계좌와 조회 범위만 허용한다.
- **Object-Level Authorization:** 객체와 요청 행위별 권한을 검증한다.
- **Server-Side Enforcement:** 서버가 인증 주체와 권한을 판단한다.
- **Revocation Enforcement:** 회수 완료 후 시작한 새 요청은 기존 권한으로 접근할 수 없다.
- **Auditability:** 접근 거부와 권한 변경을 추적한다.
- **Data Minimization:** 응답·로그에 불필요한 민감정보를 포함하지 않는다.

각 원칙의 구체적인 불변 조건과 테스트는 [보안 요구사항](security-requirements.md)을 따른다.

## 7. MVP 범위 밖의 위협

- 실제 인증정보 탈취·피싱
- 운영체제·DB 서버 직접 침해
- 내부자의 DB 직접 접근
- 네트워크 DDoS
- 금융 데이터 위변조 및 부정 이체
- 운영 수준의 감사 로그 위변조 방지·장기 보존
- 탈취된 JWT의 즉시 폐기

해당 위협의 존재를 부정하는 것이 아니라 이번 실습 범위에서 제외한다.

## 8. 안전한 검증 환경

- 실제 금융기관·제3자 서비스 공격 금지
- 격리 환경 및 합성 데이터만 사용
- 의도적으로 취약하게 만든 코드는 평가 환경에서만 실행
- 평가용 결함을 정상 배포 아티팩트에 포함하지 않음
- 발견한 결함과 검증 결과를 기록
